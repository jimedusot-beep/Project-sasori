# Elmo source recovered: protocol facts and first executable client

Reviewed October 23, 2026 (America/New_York). **The missing-app-artifact blocker is now cleared.** A broader public GitHub search found [jesserockz/love2learn-elmo](https://github.com/jesserockz/love2learn-elmo/tree/d397a7fb094079f6b1cac5605e95f74d1cb8d4b3), including a standalone `pyelmo` client. A public Aptoide archive supplied the same APK previously described in the owner's report. The original October 21 review and earlier October 23 failed-download result remain historical observations, rather than the current acquisition status.

Sasori now has an original [desktop known-password client](../../desktop/sasori_elmo.py) and [wire codec](../../desktop/elmo_protocol.py). It connects to a deliberately selected toy, responds to one challenge, requires an explicit acceptance frame, requests volume/input state, and optionally requests one built-in greeting. This is an **experimental software implementation**, not independent hardware verification. The same subset now also has a [button-based browser remote](../../docs/elmo-remote.md), with original JavaScript calculations checked against the synthetic vectors below. Existing inspection APIs remain unchanged; the laboratory's Authentication Experiment is still synthetic. Native Elmo writes remain unavailable.

## Community implementation: useful and bounded evidence

The [pinned `pyelmo` README](https://github.com/jesserockz/love2learn-elmo/blob/d397a7fb094079f6b1cac5605e95f74d1cb8d4b3/custom_components/love2learn_elmo/pyelmo/README.md) reports real-toy confirmation for authentication, play, volume-setting and touch monitoring. It explicitly leaves newer state read-backs unconfirmed. Its [client](https://github.com/jesserockz/love2learn-elmo/blob/d397a7fb094079f6b1cac5605e95f74d1cb8d4b3/custom_components/love2learn_elmo/pyelmo/client.py), constants, tests and [Apache-2.0 license](https://github.com/jesserockz/love2learn-elmo/blob/d397a7fb094079f6b1cac5605e95f74d1cb8d4b3/LICENSE) were inspected. That is **maintainer-reported hardware evidence**, not a new test on Jimmy's unit.

The comparison found behavior Sasori does not adopt: accepting empty/unknown password statuses, enabling password enrollment by default, packet logging that can include authentication material, ASCII-only password encoding, and modulo arithmetic/odd-byte padding that differs from the app at some edges. The [source-derived synthetic vectors](fixtures/source-derived-auth.synthetic.json) cover fresh non-secret inputs, preserved whitespace and UTF-16 low-byte conversion. A zero-filled even-length Fletcher input produces FFFFFFFF under the app's folding, rather than zero. These calculations test the original Sasori codec, not execution of original app methods or observed radio exchanges.

The [community sound catalog](https://github.com/jesserockz/love2learn-elmo/blob/d397a7fb094079f6b1cac5605e95f74d1cb8d4b3/tools/sound_catalog.json) identifies ID 9 as a generic greeting. Sasori exposes that single ID via explicit `--hello`; it does not bundle the catalog's transcripts or audio. A queued write does not prove the sound occurred, and disconnect is not a verified playback-stop command.

## Current evidence gaps

- **G1:** artifact acquired and internal signature/member integrity checked; Hasbro publisher identity remains unauthenticated and binary manifest metadata unparsed.
- **G2–G4:** relevant method provenance, framing, credential-byte construction and checksum/serialization are now directly inspected for the implemented subset. Source-derived synthetic tests exist. Runtime challenge size/notification framing on this unit still needs measurement; Sasori accepts only complete, nonempty even challenge payloads of 2–18 bytes and does not guess padding/reassembly.
- **G5:** source state handling is established; the stricter current-response/explicit-status policy is tested with fakes. Real session timing, unsolicited packets, rejection and reconnect behavior remain untested on this unit.
- **G6:** input/volume writer/parser facts are established. Sasori reports matching/no-matching replies and leaves unknown values unknown. No speculative battery conversion is used.
- **G7–G8:** exact unit/firmware, foreground baselines, physical greeting/recovery observations and privately entered known password remain owner-device work. No real password was collected or assumed in this review.

The [desktop procedure](../../desktop/README.md#experimental-elmo-known-password-check) is ready for an owner-run trial. The browser additionally supports [first-time password setup and guided owner recovery](../../docs/elmo-password-recovery.md). Hasbro documents a physical reset for forgotten passwords and an accessible original-app password display. Reset erases personalization; it is not a remote bypass. The original password writer above establishes the new setup frame. Sasori requires explicit opt-in, an exact unset report, at most one setup write and explicit acceptance. New synthetic tests cover these gates, interrupted/late acknowledgments and a modeled fresh connection; real password persistence/reset behavior remains unverified.

The next milestone is a real connection/authentication result and one observed greeting, rather than finding the missing app binary again.
