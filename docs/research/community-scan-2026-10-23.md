# Community scan: actionable toy-control sources

Reviewed October 23, 2026 (America/New_York). Public GitHub repository search, repository files, Reddit, maker/security project pages and public distribution metadata were inspected. Search-engine coverage missed a newer Elmo repository that a direct global GitHub repository search found. Future scans should include both, plus source-linked issues/forks and exact package/protocol symbols.

## Results that changed Sasori

**Elmo now has an actual source-backed implementation path.** [jesserockz/love2learn-elmo at d397a7f](https://github.com/jesserockz/love2learn-elmo/tree/d397a7fb094079f6b1cac5605e95f74d1cb8d4b3) supplies a standalone Python/Bleak client and a Home Assistant integration. The maintainer reports authentication/play/volume/touch tests while separating unconfirmed read-backs. The public Aptoide archive's bytes matched the earlier APK SHA-256 exactly. Sasori independently inspected relevant managed methods and added a bounded original known-password desktop client, strict status handling and synthetic vectors. See [full provenance/method review](../../experiments/001-elmo-l2l/recovered-source.md).

The [r/hackedgadgets Elmo thread](https://www.reddit.com/r/hackedgadgets/comments/761dcf/hack_a_love2learn_elmo_help/) contains firsthand flash/audio research claims and a later author's claim of a Python audio uploader. The inspected thread supplies no linked uploader implementation or complete authentication trace. Its comments are leads, not additional independent confirmation of Sasori's client. No reset, pad-shorting, flash-writing or audio-upload procedure was adopted from it. [Hasbro's connection FAQ](https://hasbro-new.custhelp.com/app/answers/detail/a_id/348/~/how-do-i-connect-my-love2learn-elmo-toy-to-the-app%3F) confirms BLE app connection and discontinued app support; it supplies no authentication bytes.

## Search outcome and next useful work

Successful leads: global repository search for Love2Learn/Elmo; the standalone `pyelmo` subtree; original app package metadata and archive; original FurBLE/LEGO/Sphero code; source-linked maker accounts. Exact searches for Elmo with `Fletcher32`, `securityChallenge` or `bleak` were noisy or sparse; a failure to find those symbols did not establish that no implementation existed. EEVblog was unavailable through the search provider's robots rules; no inaccessible forum contents are claimed as inspected. The public NonaSuomy repository had no returned issues or forks at this review.

Next prioritize actual owner-device captures against the new desktop client, then port the verified behavior into the shared web/native interface. For another toy, start with a maintained exact-family implementation or manufacturer protocol, record the model/firmware and recovery behavior, and reuse the connection/intent framework. Borrowing random bytes from a nearby-looking toy wastes effort and does not establish compatibility.

No community was contacted, no account/session was probed, and no command was sent to a physical device during this research. No unlicensed app code, firmware, audio or real authentication data is included in Sasori.
